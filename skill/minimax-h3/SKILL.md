# MiniMax H3 — общий скилл (FreeVideo, любая машина)

Работай на языке пользователя. Промпт для модели составляй по правилам H3 (описания на английском, реплики и надписи на языке оригинала). Текстовый промпт не выдавай за созданное видео. Это адаптация официальных skills MiniMax-H3 и справки FreeVideo `/guide`, а не эмуляция MiniMax Hub.
Если рядом установлен машинный скилл (например `minimax-h3-<gpu>`), загружай сначала этот общий скилл, затем машинный: машинный добавляет замеры и порядок работы конкретного компьютера.

## Inputs / Outputs / Non-goals

Вход: замысел, длительность, формат, изображения/видео/аудио, либо ID предыдущего задания. Спрашивай только о действительно неоднозначном (роль референса, смена заказанного содержания).
Выход: только промпт, если просят промпт; для генерации — проверенный файл, фактические параметры (реальная длительность в секундах, seed, quality) и честные ограничения проверки. Для нескольких планов — таблица планов с непрерывностью.
Не устанавливай модели/ноды, не меняй энкодеры, не используй платные облака, не очищай общую очередь, не отменяй чужие задания. Установка скилла не разрешает тестовую GPU-генерацию.

## Routing

- Структура промптов, режимы, камера, реплики, надписи, звук, Ref2VA → `references/prompt-guide.md` (там же готовые шаблоны).
- Длинные ролики, продолжение, склейка, ровная скорость на стыках → `references/continuity.md`.
- Параметры движка: quality/sampling/LoRA, сетка кадров, оценка времени, части, загрузка, ожидание, скачивание → `references/freevideo-api.md`.
- Что уже проверено на практике и какие у модели слабые места → `references/practice.md`.
- Реклама, 3D-сюжет, клип, бумажные стили, игровая заставка, рисованная анимация → `references/style-recipes.md`.
- Ошибки и пределы повторов → `references/failure-modes.md`; проверки и evidence → `references/production-skill-architecture.md`; происхождение правил → `references/sources.md`.

## Режим промпта — по роли референса, не по числу файлов

| Задача | Режим | FreeVideo media |
|---|---|---|
| Только текст | T2VA | без media |
| Начать с картинки (в т.ч. с последнего кадра другого ролика) | I2VA | `first` |
| Пройти от начального к конечному кадру | FL2VA | `first` + `last` |
| Прийти к заданной картинке в конце | L2VA | `last` |
| Сохранить персонажа/стиль/предмет/голос из набора источников | Ref2VA | `references` (до 3 картинок в многочастном ролике) |

Две фотографии одного героя с разных сторон — это Ref2VA (identity), а не FL2VA. Режим сервер выводит из media сам: поле `task` в задание не добавляй.

## Как строить длинное видео — выбирай по задаче

1. **Новый план (по умолчанию для фильма из планов).** Смена плана = новая генерация с референсами персонажей/места (Ref2VA) или с подготовленным первым кадром (I2VA). Так держится лицо и не копится дрейф.
2. **Продолжение с последнего кадра** (`media.first = {"from_job": "<id>", "frame": "last"}`) — когда нужен непрерывный проход камеры, непрерывное действие или переход сцены без склейки. Рабочий приём: так собирались ролики больше минуты из клипов по 10–15 с.
3. **Продолжение видео** (`continue_from`) или **одна длинная задача** (`seconds` до 60, части и склейку делает движок; `part_prompts` — свой текст на каждую часть) — когда важны непрерывное движение и звук через стык.
4. **Комбинации:** закончили одну сцену, следующую начали новым планом; внутри длинного прохода — продолжение. Не продолжай одно и то же видео бесконечно: после нескольких частей лучше новый план.
Подробно, со стыками и скоростью движения → `references/continuity.md`.

## Workflow

1. Цель: только текст или генерация. Осмотри предоставленные изображения vision-инструментом; не выдумывай содержимое недоступного референса.
2. Выбери режим и способ построения (таблицы выше). Для сложной последовательности сначала таблица планов; для одного клипа — без лишних стадий.
3. До GPU-запуска: `GET /` (ready), `GET /queue`, при необходимости `GET /capabilities` (размеры, длины, оценка времени ЭТОЙ машины). Схему читай один раз за сеанс, не по полю.
4. Зафиксируй внешность, одежду, реквизит, свет, позу и положение камеры одинаковыми словами во всех планах.
5. Составь промпт по `prompt-guide.md`; времена `[Shot N] At MM:SS.mmm` — внутри фактической длительности (см. сетку кадров).
6. JSON задания: `kind: generate`, `seconds` (не `duration`), размеры кратные 32 или `aspect`, `quality`, `release_gpu_after`; всегда `label` (короткое имя ролика) и `ref` (ключ идемпотентности: повтор с тем же `ref` не создаёт вторую генерацию); при нужде `seed`, `media`, `loras`, `continue_from`, `part_prompts`, `first_frame_reference`. Явные значения пользователя не меняй молча.
7. `POST /plan`: ошибки, предупреждения, режим, фактическая длительность, цепочка частей, оценка времени. Warnings — разобраться до запуска. Локальный r2v всегда даёт warning `Reference generation is experimental`: это свойство режима, его принимают точным `--accept-warning "Reference generation is experimental"` и пересказывают в отчёте.
8. Только при запросе генерации — `POST /jobs` (`--apply`). Сохрани ID сразу. После таймаута не повторяй POST вслепую: сверь `/jobs`, повтор — с тем же `ref`.
9. Ожидание: `GET /jobs/<id>?wait=25` отдельными вызовами; исчерпание твоего лимита ожидания не отменяет задание.
10. После `succeeded`: скачай `result.video.url`, проверь размер, декодирование, длительность, контрольные кадры (начало/середина/конец) и звук. Есть ли непрошеные субтитры. Без визуальной проверки не утверждай, что движение или непрерывность правильны.
11. Сообщи результат коротко: реальная длительность в секундах, что решено самостоятельно (дубли, разбиение), ограничения проверки.

## Quick start

Пути относительно папки скилла. В Windows — `python` и абсолютные пути с `/`.

```bash
python -B scripts/freevideo.py get /
python -B scripts/freevideo.py get /queue
python -B scripts/freevideo.py get /capabilities
python -B scripts/freevideo.py post /plan --json assets/job-t2va.json
```

Только для уже разрешённой генерации (запускает вычисления на GPU):

```bash
python -B scripts/freevideo.py post /jobs --json job.json --apply
```

Helper: только стандартная библиотека, только loopback `127.0.0.1`/`::1`, токен не печатает, сам не повторяет запросы, вывод в UTF-8 на любой консоли.

## Final review / Evidence

Готово = успешный job + полученный файл + техническая проверка + честно обозначенная визуальная/аудио проверка. Журнал — в папке задачи, не внутри скилла; токен туда не копируй.
Регрессии: `python -B scripts/test_freevideo.py`; сценарии — `assets/evals.json`. Тесты проверяют helper, не художественное качество модели.
